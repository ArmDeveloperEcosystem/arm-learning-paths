## Prepare the model data

From the ML Drift repository root, create a model data directory and download the text vocabulary. The original OpenAI vocabulary is available under an [MIT License](https://github.com/openai/CLIP/blob/main/LICENSE):

```bash
mkdir -p /tmp/sd_1_5
curl --fail --location \
  https://huggingface.co/OpenGVLab/ViCLIP-B-16-hf/resolve/main/bpe_simple_vocab_16e6.txt.gz \
  --output /tmp/sd_1_5/bpe_simple_vocab_16e6.txt.gz
```

Download the model weights in 16-bit floating-point format, available under the [CreativeML Open RAIL-M License](https://huggingface.co/spaces/CompVis/stable-diffusion-license). You need at least 2.13 GB of storage on both your host and Android device:

```bash
curl --fail --location \
  https://huggingface.co/Comfy-Org/stable-diffusion-1.5/resolve/main/v1-5-pruned-emaonly-fp16.safetensors \
  --output /tmp/v1-5-pruned-emaonly-fp16.safetensors
```

On your host computer, decompress the vocabulary and extract the model weights into `/tmp/sd_1_5/`:

```bash
gzip -dc /tmp/sd_1_5/bpe_simple_vocab_16e6.txt.gz > /tmp/sd_1_5/bpe_simple_vocab_16e6.txt
bazel run //ml_drift/samples/stable_diffusion:extract_weights -- \
  --model_path=/tmp/v1-5-pruned-emaonly-fp16.safetensors \
  --output_dir=/tmp/sd_1_5/
```

## Build and deploy the executable

Build the optimized OpenCL sample for Android arm64:

```bash
bazel build -c opt --config=android_arm64 \
  //ml_drift/samples/stable_diffusion:sd_gpu_opencl
```

{{% notice %}}
On macOS, if the Android build fails while configuring the Apple C/C++ toolchain, disable that toolchain and retry:
```bash
export BAZEL_NO_APPLE_CPP_TOOLCHAIN=1
```
{{% /notice %}}


Copy the executable and model data to `/data/local/tmp/` on your Android device, then make the executable runnable:

```bash
adb push bazel-bin/ml_drift/samples/stable_diffusion/sd_gpu_opencl /data/local/tmp/
adb push /tmp/sd_1_5 /data/local/tmp/
adb shell chmod +x /data/local/tmp/sd_gpu_opencl
```

Start the sample on your Android device from `/data/local/tmp/`:

```bash
adb shell -t 'cd /data/local/tmp && ./sd_gpu_opencl'
```

At `Enter phrase:`, enter an image description. At `Enter steps:`, enter the number of diffusion steps. For example:

```text
image of a cat in space
10
```

After image generation, the sample prints timing measurements. The output is similar to this example from a Vivo X300 with a Mali G1-Ultra GPU; your timings will vary:

```output
Init time: 20.07 ms.
Loop time: 11052.8 ms.
Decode time: 588.189 ms.
Total diffuser time: 11661 ms.
```

Init time: Time to prepare your text prompt and the starting noise for image generation.
Loop time: Time spent repeatedly removing noise to form an image that matches your prompt.
Decode time: Time to turn the model’s compact image representation into pixels and retrieve the result.
Total diffuser time: Total time for these three stages. It excludes loading the model at startup and saving the image file.

## Retrieve the generated image

When generation finishes and `Enter phrase:` returns, press **Ctrl+C** to exit the sample. On your Mac, copy the generated image from the device and open it:

```bash
adb pull /data/local/tmp/result.bmp ./result.bmp
open ./result.bmp
```

This image was generated by the validated 10-step run on the Android Mali device. Your result can differ:

ML Drift lets you reuse unified shader code across GPU backends, reducing the need to maintain separate implementations for each API. Its standalone C++ APIs and custom operation framework let you integrate GPU-accelerated inference into your own runtime and extend it with specialized operations.

## A unified shader in the sample

The sample uses Unified Compute Language (UCL) as an abstraction layer over OpenCL. For example, `ml_drift/samples/stable_diffusion/ops/diffusion_step.cc` contains this excerpt from a kernel template stored in a C++ string:

```cpp
int X = ucl::GetGlobalId<0>();
int Y = ucl::GetGlobalId<1>();
int S = ucl::GetGlobalId<2>();
if (X >= args.dst.Width() || Y >= args.dst.Height() || S >= args.dst.Slices()) return;
Type eta_cond = args.etaCondIn.Read(X, Y, S);
```

`ucl::GetGlobalId` identifies the work item's coordinates, while `args.etaCondIn.Read` expresses a tensor read without specifying its underlying GPU storage. ML Drift translates these abstractions into OpenCL source for this backend, which the driver compiles for the GPU. The same unified shader logic can target other supported backends.
